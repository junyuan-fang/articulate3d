# 改进方向

前提结论（依据见 [04-diagnosis.md](04-diagnosis.md)）：

- **分割不是瓶颈**：我们 AP50 = 0.4370 是榜上最高（linxii 0.4352），**不要去换分割骨干**
- 差距全在关节参数保留率：我们 60.4% vs linxii 77.2%
- axis 和 origin 病因不同、几乎独立（φ = −0.11），**分开改，收益可加**

收益上限估算：

```
换更强分割，保留率不变：   AP50 提到 0.50 → 0.50 × 0.604 = 0.302
修关节头，达到 linxii 保留率：0.4370 × 0.772 = 0.337
```

## 第 0 层 · 后处理（零成本，最高 val 0.3214 → 0.3812）

**全部只改 `pred_axises` / `pred_origins`，不动 `pred_masks`，所以 `AP50` 逐位不变、分割零风险。**

三个可叠加的干预，按依据强度排序：

| 干预 | val AP50_axis_origin | 依据 |
|---|---|---|
| baseline | 0.3214 | |
| **① axis 归一化为单位向量** | 0.3391 | 评测的 `diff_proj_pred_axis` 投影除的是 `norm` 而非 `norm²`（见 [04-diagnosis.md](04-diagnosis.md)），模型输出模长 0.11~1.46 |
| ② + axis 吸附到正则方向(30°) | 0.3548 | **96.4% 的 GT 轴在正则方向 5° 内**（rotation 91.7% 竖直，translation 95.0% 水平）；实测 16 例变好、0 例变坏 |
| ③ + origin 吸附到 mask 端点(2%/98% 分位) | **0.3812** | 用 GT mask + GT 轴时，铰链 **100%** 落在部件沿主方向的两端点之一，中位误差 8 mm |

**① 是纯粹的"免费"修正**（对齐评测器的实现），风险最低，应当无条件启用。

③ **必须用 2%/98% 稳健分位**，原始 min/max 版本反而掉分（0.694→0.656）——端点易受离群点影响。

我自己实现的一个较弱版本在 `/data/challenge/analysis/postprocess.py`（重力吸附 + origin 吸到掩码**最近点**），端到端复现为 0.3214 → 0.3627。上表的 ③ 用的是**沿主方向的端点**而非最近点，更强。

**状态：尚未上线。** 先在 dev 验证（配额 49 次，很便宜），用它校准 val→test 的换算比例。

### ④ 推拉门叶片规则：translation 轴的方向二选一（val 0.4395 → 0.4605）

**这是目前最后一个还能动的因子。** rotation 轴已到天花板（12 个失败全都偏 >20°，就是探针证明学不出来的侧向铰链），origin 也已经吃满，所以只剩 translation 轴。

诊断（`analysis/diag_translation_axis.py` → `diag_inplane.py`）：

平面部件的滑动方向只有**两个**物理可能，而不是一个：

| | 方向 | 例子 |
|---|---|---|
| 穿过自己的面 | 面板法向 | 抽屉 |
| 沿着自己的面 | 面内水平方向 | 推拉门 / 推拉窗 |

原来的规则假设永远是法向，所以 9 个推拉叶片全错，而且**恰好错 90°**。PCA 法向本身很准（中位误差 0.70°，模型头是 5.54°），错的不是方向估计，是**二选一选错了**。

**模型不能用来做这个选择**：它学到了"抽屉往外拉"的先验，在 5/5 需要面内的样本上都更靠近法向（31.9° vs 58.1° 这种）。

判据改成纯几何的"成对叶片"：

```
两片推拉门必须在【不同】平面上、相隔约一个叶片厚度（这样才能互相错开），
并排、同高、尺寸相当。
一排/一摞抽屉共面（间距 ≈ 0），共面的面板无法互相通过。
```

val 上平面间距 `dn` 完全分开两类：面内滑动 0.008–0.035 m，抽屉类 0.000 / 0.089 / 0.245 / 1.30 / 1.84。

| | AP50 | axis | origin | joint |
|---|---|---|---|---|
| 无叶片规则 | 0.5716 | 0.4836 | 0.5018 | 0.4395 |
| **+ 叶片规则** | 0.5716 | **0.5046** | 0.5018 | **0.4605** |

AP50 与 origin 逐位不变（只碰 `pred_axises`），+0.0210 全部来自 axis 保留率（84.6% → 88.3%）。

**关键教训：一定要"成对"判据，不能只判自己平不平。**

只用单边 planarity 阈值时是个**尖峰不是平台**——0.05 处 +0.0124，但 0.03 和 0.08 都掉到基线**以下**（9 个正样本里 8 个来自同一个场景 `5656608266`，等于在一个场景上拟合）。加上"两片都平 + 同高（差 <15%）"之后整张网格都在基线之上：

```
planar\htol   0.10    0.15    0.20    0.25    0.30      (基线 0.4395)
0.03        0.4406  0.4432  0.4432  0.4432  0.4432
0.05        0.4605  0.4605  0.4605  0.4605  0.4605
0.08        0.4530  0.4530  0.4477  0.4477  0.4413
0.12        0.4484  0.4484  0.4432  0.4414  0.4351
0.20        0.4484  0.4484  0.4432  0.4378  0.4316
0.35        0.4460  0.4439  0.4361  0.4296  0.4235
```

htol ≤ 0.15 时 planarity 从 0.03 到 0.35（12 倍范围）全部为正，最差 +0.0037。这才敢上线。

**还需要一条"门那么高"的下限（`MIN_LEAF_H=0.45` m）。** val 上看不出来（9 个正样本最矮 0.50 m，加不加都是 0.4605），但 test 上不加会把 0.23 m 和 0.33 m 的面板判成推拉门叶片——**一排抽屉也是等高、近似共面的**，而其中一个还是该场景分数最高的预测（0.95）。23 cm 高的东西不是门。

**重要：统计"改了几个"要看全部预测，不能只看高分的。** test 上 score>0.3 的只改了 3 个，看起来规则几乎不起作用；但连低分一起算是 ~50 个。AP 积分整条 PR 曲线，低分那段照样计入。

**两个已验证失败的做法**（别再试）：

1. **平面部件无条件取法向**（去掉 25° 一致性门控）：匹配实例保留率说该涨，实际 AP50_axis 掉 ~0.010（0.4836 → 0.4737）。原因：诊断只看 95 个高分匹配实例，而 AP 积分整条 PR 曲线，低分预测那段面板几何很不可靠。**以 AP 为准，不要以匹配保留率为准。**
2. **让模型来二选一**：5/5 选错。

## 第 1 层 · 参数隔离：保住分割的正解

仓库已内置，不用自己实现：

```python
# trainer.py:113
config.general.freeze_backbone          # 冻结骨干

# trainer.py:84   PEFT LoRA
general.LORA.{USE_LORA, R, ALPHA, DROPOUT, TARGET_MODULES}
```

冻结骨干 + decoder、只训关节头，这比重训全网络安全得多——重训有掉分风险，而我们的分割**已经是榜首**，没有理由拿它冒险。

### ⚠️ 但只冻参数是不够的：BatchNorm buffer 会漂

**我最初写「冻结后 AP50 数学上不可能变」，这是错的。**

`requires_grad_(False)` 只冻**参数**。BN 的 `running_mean` / `running_var` 是 **buffer**，
只要模块处于 `train()` 模式，每次前向都会被刷新。实测（`analysis/check_ckpt_diff.py`，
对比 `mov_trainval.ckpt` 与 `v2_origin_only@ep4`）：

```
BN buffer  124 个 → 124 个全部漂移       ← 漏掉的路径
非 BN 参数  306 个 →   6 个变化，全部属于 origin_embed_head   ← 参数冻结本身是对的
```

危害有两层：

1. **污染归因**：推理用的就是 running stats，骨干特征、`pred_masks`、`pred_axises` 全都跟着变，
   于是 `AP50` / `AP50_axis` 并没有被冻住，origin 的消融实验失去对照意义。
2. **train/test 失配**：统计量漂向 4 m crop 的分布，而推理跑的是整场景。

**这不是理论担忧，它真的污染了一整轮结论** —— 见 [06-finetune-design.md](06-finetune-design.md) 的 BN 一节。

修法：让被冻结的 BN 全程保持 `eval()`。已实现在 `trainer.py` 的 `train()` 覆写里
（Lightning 每个 epoch 都会重新调 `.train()`，所以必须覆写而不是一次性 `.eval()`）。
关节头全是 Linear/ReLU，不含 BN，所以一刀切冻结所有 `_BatchNorm` 正是想要的行为。

**真正成立的一处失配**：

```python
loss_axises_vec = 1 - torch.sum(map_axises_norm * target_axises_norm, dim=1)   # 1 - cos
```

损失用 `cos`，评测判据用 `|cos|`（`match_criteria_MA_pred` 取了 `np.abs`）。**轴反向 180° 评测判定为完美命中，损失却给最大惩罚。** 开关：`loss.axis_loss_abs_cos`。

## 第 3 层 · 换参数化（文献 SOTA 做法）

三条，都直击诊断出的病因：

### ① axis：分类 + 残差，而不是自由回归 3D 向量

诊断显示轴分布极度双峰（竖直/水平），自由回归被主导模式吃掉 —— **模型塌陷成了重力先验，横向铰链 8/8 全错，且平凡先验比模型还准（0 胜 9 负）**。

改成「竖直 / 水平 / 其他」三分类 + 类内残差回归，横向铰链就不会被淹没。这很可能就是 linxii 轴保留率 95% 而我们 87% 的差距所在。

### ② origin：部件相对的归一化坐标，而不是世界坐标

[ANCSH (CVPR'20)](https://openaccess.thecvf.com/content_CVPR_2020/papers/Li_Category-Level_Articulated_Object_Pose_Estimation_CVPR_2020_paper.pdf) 的核心结论：**在归一化的规范空间里预测关节参数、再变换回相机系，比直接在相机系回归显著更好。**

我们的诊断给了独立佐证：
- origin 误差**与部件尺寸无关**（Spearman 0.006）→ 模型在全局坐标里「盲回归」，没有利用部件自身的尺度
- 「吸到预测掩码最近点」这么粗暴的操作就白赚 rot +0.048 → **预测的 origin 经常悬在部件外面**

最小改动版本：把 origin 预测成「相对预测掩码质心的偏移 ÷ 部件 extent」。

同时该头有 29% 的向质心收缩偏差，可用更重的边缘/极值监督或分类式（bin + 残差）回归缓解。

### ③ 把 axis + origin 当成一条直线预测，而不是两个独立量

评测判据本身就是「点到直线的垂距」—— **直线才是真正的几何对象，origin 只是它上面的任意一点**。[Plücker 坐标](https://www.sciencedirect.com/science/article/abs/pii/S002192900500429X)是直线的自然无冗余表示，天然消掉沿轴滑动的自由度。

这条改动最大但最「对」，也顺带解决了第 2 层的损失错配问题。

### 更激进：稠密投票代替单 query 回归

[RPMArt](https://r-pmart.github.io/) 用**点元组投票**（从局部特征投票关节参数），而不是从单个 query 向量回归。投票聚合局部证据，对小部件更鲁棒 —— 正好对应诊断里「小部件（<2k 点）轴通过率 0.79–0.83 vs 中等部件 0.96」。

工程量大，需重构关节头。
