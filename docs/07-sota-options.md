## 1. 文献调研：为什么 SOTA 大多用不上

| 方法 | 为什么不适用 |
|---|---|
| [Dynamic 3D Gaussians (BMVC'25)](https://arxiv.org/abs/2506.22718) | 需要**点云序列**做运动分割，我们只有单帧静态扫描 |
| [PARIS (ICCV'23)](https://openaccess.thecvf.com/content/ICCV2023/papers/Liu_PARIS_Part-level_Reconstruction_and_Motion_Analysis_for_Articulated_Objects_ICCV_2023_paper.pdf) / GaussianArt / SplART | 物体级 + 多视角/两状态重建 |
| [ATOP](https://arxiv.org/html/2502.07278v1) | 文本驱动生成关节，不是从扫描里估计 |
| [ANCSH](https://openaccess.thecvf.com/content_CVPR_2020/papers/Li_Category-Level_Articulated_Object_Pose_Estimation_CVPR_2020_paper.pdf) | **思想可用**（规范空间里回归关节参数优于全局坐标），已吸收进 origin 头设计 |
| [RPMArt](https://r-pmart.github.io/) | **思想可用**（局部特征投票替代单 query 回归），工程量大，未做 |

真正对口的是 3D 实例分割那一侧的工作：
[Open3DIS](https://arxiv.org/html/2312.10671v3)、[OnlineAnySeg](https://arxiv.org/pdf/2503.01309)
都表明 **superpoint 引导的 mask merging 能显著提升 recall**——而 recall 正是我们的天花板。

## 2. ✅ 最大机会：superpoint / segments（Mask3D 原生能力，一直没开）

```
ScanNet++ 的 segments.json（过分割）已下到 227/279 个场景（全量下载仍在进行）
但我们全程 train_on_segments=false, eval_on_segments=false
预处理数据里没有 segment 字段
```

这是 **Mask3D 论文自己的核心机制**，在 ScanNet 上有显著提升，原理正打在痛点上：
mask 被约束到几何一致的 superpoint → 边界更干净 → IoU 更高 → **更多实例跨过 0.5 阈值 → recall 上升**。

需要做的：把 ScanNet++ 的 `segIndices`（定义在原始 mesh 顶点上）映射到预处理后的体素化点云。
最近邻即可，和 `get_subset_pcl_indexs` 里的做法同构。

**这是唯一可能带来量级提升的方向**，其余都是小修小补。

## 2.1 ❌ superpoint 吸附：三种变体全灭（2026-08-11）

   直接开 `eval_on_segments` 会把整场景当一个 segment。
2. 我先跑了干预才回头测天花板，顺序反了，白费一次崩到 0.2244 的实验。

自己从 xyz+法向算 superpoint（`analysis/make_superpoints.py`，Felzenszwalb + kNN 图），
再把预测 mask 吸附上去（`analysis/snap_masks_to_superpoints.py`）：

| 变体 | val AP50 |
|---|---|
| **基线（不动）** | **0.5716** |
| 保守修补 0.05/0.95（只填 >95% 覆盖、只删 <5%） | 0.5699 |

**单调：干预越多越差，极限是什么都不做。**

表示能力天花板（`analysis/gate_superpoint_ceiling.py`，用 GT 挑最优 superpoint 集）：

| 粒度 | oracle IoU≥0.5 | 中位 | 小部件(<500点) 中位 |
|---|---|---|---|
| 中位 100 点 | 50.7% | 0.519 | **0.000** |
| 中位 12 点 | 91.4% | 0.851 | 0.675 |

粗粒度天花板（50.7%）**比我们现有的 63.8% 还低**，小部件完全无法表示——432 个 GT
里有 156 个不到 500 点。细化后天花板到 91.4%，表示能力不再是瓶颈，**但吸附照样掉分**。

**根因：模型学的是语义边界，superpoint 编码的是几何连贯，两者不重合。** 柜门和柜框
共面、法向连续，几何上没线索分开；门板自己表面反而可能有法向突变被切碎。

⚠️ 这只否定了**后处理版**。`train_on_segments` 重训是另一回事（让网络以 segment 为
预测单元），但天花板分析说小部件仍会受损（中位 0.675）。

## 3. ❌ 已排除：靠推理不确定性做集成

想法：`seed: null` 让每次推理不同，跑 N 次合并 mask 提 recall，零训练成本。

**实测否掉了**——两次独立推理对比：

```
A 的每个实例在 B 中的最佳 IoU：中位 1.000，97% 的实例 IoU > 0.5
```

**两次跑出来 97% 完全一样。** 种子噪声只影响极少数边界样本（那 ±0.002 的波动就是它），
没有多样性可供集成。零成本验证，省下一整晚。

## 4. ⚠️ 增广被一个 bug 堵死

`datasets/semseg.py:1363-1365`，翻转增广时的关节标签变换：

```python
for axis in flip_axis:
    arti_anno[inst_id]['origin'][axis] = flip_axis[axis] - arti_anno[inst_id]['origin'][axis]  # origin 正确
    arti_anno[inst_id]['axis'] = - arti_anno[inst_id]['axis']                                   # 轴整体取负 <- 错
```

沿某坐标轴翻转，方向向量**只应翻转那一个分量**（`axis[i] = -axis[i]`）。整体取负等价于轴反向 180°。

评测判据取 `|cos|` 对反向不敏感，所以最终指标看不出来；
但**训练损失用的是 `cos`**，会把被污染的样本当成「轴完全错」惩罚（`axis_loss_abs_cos` 开关因此有意义）。

目前无实际伤害，因为 `flip_axis` 的赋值在 **669 行被注释掉**，且 `volume_augmentations_path: null`
—— **整个几何增广是关着的**。

**份量**：195 个训练场景、零几何增广，而我们最大的痛点恰恰是 val→test 只迁移 1/3，
典型的泛化不足特征。修好这个 bug 能同时解锁训练增广和真正的 TTA
（仓库的 `is_tta` 目前只是重复裁剪 5 次，没有旋转翻转，对整场景推理反而有害）。

## 4.5 ✅ 从 linxii 分数逆向的几何先验：全部验证通过（2026-08-06）

榜单法医学推出三个假设，实测两胜一负：

| 假设 | 结果 | 数据 |
|---|---|---|
| **平移轴 = 面板法向**（部件 PCA 最小延展方向压平到水平面） | ✅ **大胜** | 模型方位角中位误差 5.54°，PCA **0.70°**；失败样本不重叠，"一致(<25°)时信 PCA"混合 86.3%→91.6% |
| **铰链在把手对面**（用 inter 模型预测的把手，选远端） | ✅ 有效 | 选边"正确率"反而略降（88.9→86.1%）但 **origin<0.25 通过率 78.3→82.8%**——错的地方本来两端都过不了，对的地方才是决定成败的门 |
| 宽扁部件→横向铰链 | ❌ 死刑 | 精确率 8-9%；横向铰链里有 0.45×0.16 的小盒状部件，"宽扁门板"假设不成立 |

端到端叠加（`postprocess2.py --steps pca,endpoint --handles <inter_preds>`，AP50 恒定 0.5716）：

```
baseline                0.3215
+ 分箱 warm-start        0.3743
+ PCA 平移轴             0.4049   (+0.031)
+ 把手对面选边           0.4306   (+0.026)   ← 当前 val 最好，全部免训练
```

要点：translation 的 `MAO_ST` **就等于它的 MA**（评测对平移跳过 origin），所以方位角命中率直接抬最终指标的半边。
把手来源是**预测的** inter 模型输出（test 也有，跑 inter_test 时已产出），全流程可部署。

## 4.6 🔬 待验证：把 axis 当流形量而不是自由 3D 向量（黎曼几何）

**为什么这个想法有道理，机制很具体。** 现在 rotation 轴头**完全塌到重力方向**——
实测 2854 条 rotation 预测里 95.6% 恰好是 `[0,0,1]`，剩下 4.4% 是错的。这不是
"估计得不够准"，是优化坍缩。而已记录的两次修复失败都指向同一个原因：

- v6 锚点分类头：softmax 先验墙后面梯度 O(1e-5)，**分类器证明学不动**（§2.6）
- 冻结特征上的探针：5 层 FPN 全部无信号

轴的真实定义域是 **RP²**（方向且有正负号等价），不是 R³。现在的做法（自由回归
3D 向量 + 事后归一化 + `1-|cos|` 损失 + 离散锚点 softmax）在这个流形上都是近似的。
三个可落地的改法：

| 改法 | 现状 | 黎曼版本 | 为什么可能有用 |
|---|---|---|---|
| 聚合 | 逐点 axis 线性平均 | Σ aᵀa 的主特征向量（RP² 上的 Fréchet 均值） | 线性平均会让正负号相反的投票**互相抵消**，这正好是"塌到某个主方向"的一种成因 |
| 参数化 | 锚点 + 残差线性相加再归一化 | 锚点处切空间 + `exp` 映射 | 残差变成流形上有度量意义的量，且**去掉离散 softmax**，绕开先验墙 |
| 损失 | `1-\|cos\|` | 测地距 `arccos\|cos\|` | 两者梯度形状不同；`1-\|cos\|` 在接近对齐时梯度→0，测地距是常数 |

**中间那条是关键**：先验墙是"离散选择 + 高温 softmax"造成的，换成连续流形回归就
不存在这个墙。这是目前唯一一条**针对已知失败原因**的路，不是又一个碰运气的规则。

进一步的：axis + origin 合起来是 3D 空间中的**一条直线**，其自然空间是仿射
Grassmannian，用 Plücker 坐标参数化。这样两个量在一个几何对象里联合回归，
而不是两个独立的头——评测判据本来也是按"直线"来判的（点到线距离）。

**成本：必须训练，不是后处理。** 后处理这条线已经到顶（见下），所以这是唯一还有
量级空间的关节侧方向。**未验证，先别写进论文当结论。**

## 4.7 ✅ 横向铰链的**方向**其实一直都在——缺的是**选择器**（2026-08-11）

之前一直把横向铰链当"信息不存在"。**这个结论是错的，至少一半是错的。**

`analysis/gate_geometric_anchor.py`：底铰门（烤箱/洗碗机）的转轴 = 面板的**面内水平
方向**（就是推拉门规则里已经在算的 `inp`）。7 个横向铰链上实测：

```
scene         gravity  panel in-plane  planarity
9859de300f       90.0             0.3      0.014
5654092cc2       90.0             0.7      0.019
5654092cc2       90.0             2.3      0.016
1366d5ae89       89.5             3.7      0.536
38d58a7a31       89.9            14.9      0.675
5654092cc2       90.0            20.3      0.555
324d07a5b3       90.0            59.6      0.249
                        5/7 在 15° 内，中位 3.7°
```

天花板：`{gravity, panel in-plane}` 的 oracle 让 rotation 通过率 **93.9% → 96.7%**（+2.8pp）。

**为什么模型拿不到**：`_axis_bin_residual` 的 anchor 1 是 `free` 拍平来的，而 rotation
的 `free` 已经塌成 Z，拍平出来是数值残渣（`mask3d.py:660` 的 `>1e-4` 兜底还会直接退回
`free`≈Z）。**锚点集里压根没有这个方向。**

同一次推理、同一批匹配实例上的正面对比（`AXIS_BIN=false` 拿 `free`，
`gate_anchor_oracle.py` vs `gate_geometric_anchor.py`）：

| anchor 1 来源 | 8 个横向里 <15° | 中位 | oracle 通过率 | 相对当前空间 |
|---|---|---|---|---|
| `free` 拍平（现设计） | **1/8** | 35.2° | 93.9% | **+0.6 pp** |
| 面板面内水平（几何） | **6/8** | 4.8° | 96.7% | **+3.3 pp** |

⚠️ **这否掉了 §4.6 的主线。** 原方案是"拆掉 softmax 先验墙让分类器能学"，但即使
选择器完美，它能选的候选本身还差 35°——天花板只有 +0.6pp。**病根不是选择器不可训练，
是锚点集里没有正确的方向。** §2.6 记的"12 epoch 只动 +0.0002"当时归因到先验墙，
现在看至少有一半是锚点的问题。**先换锚点，再谈选择器。**

### ❌ 但选择器仍然是死结：基率问题（第 11 个探测器）

`analysis/test_handle_hinge_axis.py`：用"把手在上方 → 底铰，把手在左右 → 竖铰"
（这条物理我们已经在用来选 origin 的边，但从没用来定方向）。

```
                 dz/height  din/width   ratio
横向 中位            0.37       0.02     1.83
竖直 中位            0.05       0.25     0.19      ← 差一个数量级，信号是真的
```

但阈值扫下来精度只有 8.7%~12.5%，净收益全负。**原因是基率**：6 vs 150，患病率 3.4%。
判对赚 1、判错赔 1，所以要 50% 精度 ⇒ **需要特异度 >97%**，即 150 个竖直里最多误报 4 个。
`ratio>0.8` 的竖直就有 42 个。

**这解释了为什么前 10 个探测器全在 8%~50% 之间打转——不是特征选得不好，是任何
单一手工特征都到不了 97% 特异度。** 想过这道坎只能靠**学出来的多特征组合**。

### 由此得到的具体训练方案（取代原来笼统的"黎曼参数化"）

1. **换锚点**：anchor 1 从「free 拍平」改成「面板面内水平方向」——让那一位的选择
   *有意义*（之前选了也没用，因为候选本身是垃圾）
2. **拆先验墙**：去掉/降温 `axis_prior_temp=10` 的 prior 项，或改成切空间连续回归
   （§4.6），否则梯度 O(1e-5) 照样学不动
3. **只训那一位分类器**，其余全冻
4. **类别不平衡按 §2 的教训处理：一次只用一种重平衡机制**（v4 就是同时用了
   3× 过采样和 5× 加权才崩的）

## 4.8 ⭐ 目标改成 0.41 之后：origin 才是主战场，而且**不需要重训**（2026-08-11）

`joint ≈ AP50 × r_axis × r_origin`。当前 test：`0.4370 × 93.85% × 82.42% = 0.3385`。

| 情景 | joint |
|---|---|
| axis 做到**完美** | 0.360 ❌ |
| **origin 做到完美** | **0.410** ✅ |
| AP50 0.437→0.50 + 两项都改善 | 0.422 |

**axis 就算做到 100% 也只有 0.360。** 我之前两天都在抠 axis（它已经 93.85%、天花板 96%），
方向是错的。origin 只有 82.42%，是最弱的一环。

### 关键测量：origin 的 mask 天花板是 100%

`analysis/gate_origin_oracle.py`（180 个匹配 rotation）：

| | 通过率 | 中位偏离 |
|---|---|---|
| 当前部署 | 85.0% | 0.072 m |
| 最优端点（选边 oracle） | 88.3% | 0.065 m |
| **mask 内最优点（mask 天花板）** | **100.0%** | **0.006 m** |

**每个实例的 mask 里都存在一个距 GT 轴线 <0.25m 的点，中位只有 6 毫米。**
所以：


### ❌ 但放置规则重设计也失败了（同日，四个实验）

| 尝试 | 结果 |
|---|---|

| 三种选边器（手把 / 模型 origin / 组合） | **全部 85.0%**，一模一样 |
| **学出来的选边器**（几何特征 + 留一场景 CV） | **78.9%**，比手写的还差；仅 1.7σ 高于置换零假设 |

学习用的特征：候选点周围非部件几何的密度与计数（"铰链边贴着框"）、到把手距离、高度、
沿 d 的局部分布。刻意**排除模型自己的 origin 头**——它在 train 上是记忆过的，
用它做特征会把权重学歪。

**结论：origin 的 15% 缺口里，答案确实在候选集里（mask 天花板 100%），但我们没有
任何信号能把它选出来。** 这和横向铰链是同一种病：表示不是瓶颈，**选择**才是。

⚠️ 又踩了一次记过的坑：深度方向第一版用原始 min/max 而非稳健分位，把假设误判成
灾难性的 73%（真实是 84-86%）。**取极值一律用稳健分位。**

### ❌ 系统性信号清单：没有未被利用的输入（2026-08-11）

统一框架：**铰链边定了，axis 和 origin 同时定**（轴沿着那条边，origin 在边上）。
所以问题归结为"两条候选边里哪条是铰链边"。`analysis/inventory_hinge_signals.py`
逐个量每个物理线索单独的 AUC（156 个可解实例，含置换零假设）：

| 信号 | AUC | 判读 | 单独选边准确率 |
|---|---|---|---|
| **handle_dist** | **0.820** | **informative (12.2σ)** | **90.4%** |
| gap_beyond（边外空隙） | 0.567 | weak (2.0σ) | 57.1% |
| crease（法向折痕） | 0.519 | chance | 53.8% |
| colour_diff | 0.493 | chance | 48.7% |
| contact（贴静态几何） | 0.449 | chance（略反向） | 37.8% |
| colour_var | 0.435 | chance | 35.9% |

沿**整条边**采样测量（不是端点周围一个球——那是上一次失败的写法）。

**结论：RGB 和法向携带的信息为零。** 唯一有信号的是把手，而它早就在用。
这也解释了 §4.8 里学出来的选择器为什么是 78.9%——它在几个随机特征上拟合噪声，
反而破坏了把手这个唯一有效的信号。

**推理期可用的输入已经全部盘过并榨干。**（col 9 semantic 和 col 12 inter_id 是 GT，
推理时没有；col 11 segments 全是 0。）

### ❌ 骨干特征探针：新 head 也救不了（`analysis/probe_hinge_from_features.py`）

"不重训分割、只训一个用上所有特征的新 head"——测了，不行。用 `_axis_bin_residual`
的那 256 维输入（query + mask-pooled 点特征），137 个实例，留一场景 CV + 置换零假设：

| 任务 | 指标 | 零假设 | 结论 |
|---|---|---|---|
| 「把手规则在这里会选错」 | AUC **0.264** | 0.499±0.065 | 低于随机；14 个正样本按场景聚集，是 LOSO 假象，取反不可迁移 |
| 「铰链沿宽度在哪」（回归） | R² **−0.301** | −0.213±0.115 | **0.8σ，零信号** |

**冻结骨干时，新 head 只能利用特征里已有的信息，而信息不在里面。** 要得到新特征
就必须解冻骨干 = 重训。

⚠️ 同时修正 §2.6 的引用方式：那次"探针证明信息不存在"只有 **7 个正样本**，
统计功效不足以证伪。今天这个 137 样本的测试结论相同，但**只有后者是有效证据**。

### ❌ 用 `inter_mask` 配对监督重训关节头：目标本身不值得达成

思路是：把手是唯一有信号的线索（AUC 0.820），而 GT 的 `h5[part]['inter_mask']`
给出了**把手↔部件的配对**，我们从没用过——拿它做辅助任务训练，也许特征里能长出
铰链边的概念。

先测天花板（`analysis/gate_gt_handle_ceiling.py`）：

| 选边所用的把手 | origin 通过率 |
|---|---|
| 预测把手（当前部署） | **85.0%** |
| **GT 把手（该部件自己的）** | **80.6%** ← 完美反而更差 |
| GT 把手（场景内任意） | 83.3% |
| 两端点 oracle | 88.3% |

**把手做到完美也不涨，反而掉。** 大概是预测那条路有 bbox 过滤 + "退回模型 origin"
的兜底，遇到位置居中的把手时兜底更对；GT 单个质心没有这层保护。

⚠️ **差点误报**：第一版把 `inter_mask` 当成场景级掩码，得到 55.6%，本来要当成
"GT 把手比预测还差"的发现报出去。实际 **`inter_mask` 的长度是该部件自己的点数**，
是部件内的局部布尔索引。用局部索引去索引整个场景 = 取到完全无关的点。
**任何反常到不合理的结果，先怀疑自己的解析。**

**下一步不在后处理里。**

### 关节侧后处理已到顶（2026-08-11 重新诊断）

val 上匹配实例的 axis 通过率：**rotation 93.9% / translation 95.8%**。

- rotation 强制竖直前的 12 个失败拆开：**7 个** GT 是水平轴（横向铰链，10 次尝试
  全灭）、**4 个** GT 本身倾斜（23.4°/29.7°/35.0°/44.7°，吸附规则同样够不着）、
  1 个是唯一那条非竖直预测（已被强制竖直修掉）。
  **所有 rotation 预测都恰好是 `[0,0,1]`**，所以 93.9% 就是"GT 有多少落在竖直
  15° 内"——这是数据给的上限，不是模型的。
- translation 的 4 个失败：2 个是 15.2°/16.8° 的擦边球，1 个 score 0.02，
  1 个是没有配对叶片的推拉门。

**结论：不训练的话，axis 这条线已经没有量级空间了。** 剩下真正的大头是 mask
recall 70.5%（卡死 AP50=0.571），那要重训分割分支。

**已排除**：换骨干（我们 AP50 榜首，已决定不换）、LoRA（`TARGET_MODULES` 含分割分支，必然动 AP50）、
5.5 m crop（实测无收益，见 [06 §11](06-finetune-design.md)）、种子集成（见 §3）、
Gaussian/多视角类方法（数据形态不匹配）。

## 9. ❌ 续训/精调的 coarse-to-fine 陷阱（v9_fullaug 与 inter 精调崩溃的真凶，2026-08-25）

`use_coarse_to_fine=true` 的课程是 `radius = c2f_rad * decay^floor(epoch/alpha)`（semseg.py:585），
alpha=100 意味着**前 100 个 epoch 训练目标 mask 一直被膨胀 0.1m**。released ckpt 已训完整个课程
（膨胀→0），任何从它出发的续训若不关 c2f，等于重新教模型输出膨胀 10cm 的 mask：
- inter 精调 60ep：val AP50 0.536 → 0.008（AP25 存活 0.20，症状特征）
- v9 全网络重训 120ep：mask AP50 0.572 → 0.402（epoch 100 衰减触发时分数跳升，行为吻合）
- 杂交实验（tuned 权重 + baseline BN buffers）不恢复 → 排除 BN 漂移，锁定 c2f。

**修复后（C2F=false, LR 1e-5, flip-only, 60ep）精调不再崩溃但仍低于 baseline（0.522 < 0.536）**：
官方 1160+680 epoch 的底子，24GB 单卡一天内追不上。双模型提案集成同样被 val 否决（0.587 < 0.605）。
结论：**本届挑战的 mask 提升靠后处理，不靠重训。**
